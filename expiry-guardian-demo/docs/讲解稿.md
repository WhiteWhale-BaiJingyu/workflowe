# 六镜头讲解稿

镜头1：这是约100×60米的一层卖场示意布局，所有经营数字来自模拟数据；空间位置不表示企业真实货位。
镜头2：彩色区域属于本系统研究范围；灰色区域另行研究，不对其套用当前短保批次模型。
镜头3：冷藏区红色表示过期，橙色表示临期高风险；颜色来自 X2 批次诊断，不代表实际企业监测结果。
镜头4：点击货位，再从批次列表查看 X4 决策、X5 审核后的推荐。完整候选方案请看文字审批单，三维接口没有候选明细。
镜头5：合规状态来自 X5；通过规则检查仍需人工审批。缺少字段的批次显示未提供，不推断为通过。
镜头6：回填实际执行的推荐方案后，由 X8 判断能否更新模拟校准；重新生成后比较预计未售出成本，不保证一定下降。

## 元素与节点对应

- 建筑、地面、收银、货架：纯展示几何，不来自经营工作流。布局、货位、分区常量在 web/scene.js；固定21个货位，范围内批次按 zone、剩余天数排序后依次轮转聚合，不能当成真实货位导航。
- 范围内聚合堆：x1 质检后的本门店全部批次，经 x2 分级、xviz 输出后聚合到固定21个货位。一个堆对应一个货位，堆高取决于总件数，颜色取该货位最高风险；名牌展示全部批次数和件数，点击列表再看单批审批卡。筛选使不命中货位淡出并聚焦镜头，不改工作流。
- 区域：xviz 根据品类及商品名称映射 cold_dairy / bakery / packaged_short；本界面的区域面积没有销量含义。
- 单批颜色、剩余天数、原因：x2 tier / days_left / cause。预计成本风险用成本乘基线预计未售出量；不是销售额。
- 推荐方案、预测售出、未售出、客群：x4 决策，x5 审核后经 xviz 输出。只有有处置方案的批次有这些字段，过期并不自动伪造一份推荐方案。
- 指标：x4 base_loss、rec_loss、gain，范围是需决策批次；gain 是方案利润增量，不能解释成企业实际收益。X5 如触发回退，meta 指标仍沿用原 X4 口径；卡片为 X5 审核后的结果。
- 客群匹配：x3 及客群会话变量参与 x4；使用 /api/ask 调整客群后需重新生成清单。
- 合规卡片：x5 compliance_status。触达文案来自 x6，最终审批单来自 x7 的文字回答；未把文本强行转成结构化字段。
- 底部链路：前端定时进度动画，不读取 Dify 节点执行状态；动画会循环，结束只表示 HTTP 调用完成。
- 复盘：x8 从当前会话 last_plan 读任务元信息，@推荐 匹配执行方案，再按门店与品类更新校准；不会训练模型。
- 相机、小地图：浏览器三维相机位置，鸟瞰时可超出地图边界，不表示员工定位。

## 准确指令依据

已直接读取来源 YAML 的 x0、x8：生成示例 `门店A 今日临期处置清单 日期2026-10-24`；日期由 x0 的「日期YYYY-MM-DD」识别。复盘 `复盘 任务<task_id>，B012=18/2@推荐`；批次示例仅说明格式，不保证该批次存在。X8 使用正则识别字母+至少两位数字，数量为非负整数。任务号来自当前 last_plan，输入任务号不被核验；本机代理据当前计划验证批次。当前 /api/review 约定用户确认执行推荐方案，不支持替代方案；替代方案可通过问答框按原工作流格式手工提交。
